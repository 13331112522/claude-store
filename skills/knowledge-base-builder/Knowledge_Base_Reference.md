## 一、Karpathy LLM Wiki 核心架构与完整流程

### 1. 核心理念

彻底区别于传统RAG「每次查询从零重新检索」的模式，Karpathy将LLM定位为**知识增量编译器**：

- 知识仅需一次「编译」，就会被整合为持久化、互相链接的Markdown Wiki，而非临时索引

- 每新增一份资料、每一次提问探索，都会让知识库持续复利增长

- 核心定位：**Obsidian是IDE，LLM是程序员，Wiki是可迭代的代码库**

### 2. 三层不可破的核心架构（Karpathy 官方标准）

|层级|目录/文件|写入权限|核心规则|核心作用|
|---|---|---|---|---|
|原始事实层|`raw/` 目录|仅用户可写入，LLM只读|**永不修改、只增不减**，是唯一事实源|存放原始资料：网页剪藏、论文、PDF、会议纪要、播客文稿、代码、原始笔记，所有内容保持原生格式不变|
|知识编译层|`wiki/` 目录|仅LLM可写入，用户只读|LLM全权维护，用户不直接编辑|存放编译后的结构化知识：概念页面、实体页面、摘要、对比分析、交叉引用链接，是知识库的核心资产|
|规则约束层|根目录 `CLAUDE.md`|用户+LLM共同迭代|所有LLM操作必须严格遵守此文件|知识库的「宪法」，定义Wiki结构、命名规范、工作流程、操作边界，让通用LLM变成严格的知识库维护者|
### 3. 两大核心导航文件

1. **`index.md`** **（内容导向总目录）**

    - 存放位置：`wiki/` 根目录

    - 核心规则：LLM每次Ingest后必须更新，按「实体/概念/来源/主题」分类，每个页面附带1句话摘要+双向链接

    - 作用：LLM回答问题时**必须先读此文件**，定位相关页面再深入阅读，中等规模（100+份资料）无需向量数据库即可精准检索

2. **`log.md`** **（时间导向操作日志）**

    - 存放位置：根目录

    - 核心规则：**只追加、不覆盖、不删除**，每条记录固定格式 `## [YYYY-MM-DD] 操作类型 | 描述`

    - 作用：记录所有Ingest/Query/Lint操作，形成知识库演进时间线，同时让LLM识别已处理的文件，避免重复操作

### 4. 三大核心操作（完整工作流）

#### 操作1：Ingest（知识录入/编译）

这是知识库的核心增量流程，单份资料触发完整流程仅需3-5分钟，人工仅需审核要点：

1. 用户将新资料丢入 `raw/` 对应子目录，无需任何预处理

2. 向Claude Code发出Ingest指令，LLM执行以下操作：

    - 读取原始文件，提取核心论点、关键概念、核心数据、核心实体

    - 与你确认核心要点，引导你标注需要重点关注的内容

    - 为该资料生成专属摘要页面，存入 `wiki/sources/`

    - 更新 `index.md` 总目录

    - 增量更新Wiki中所有相关的概念/实体页面（单份资料通常触发10-15个页面更新）

    - 标记新旧内容的矛盾点，标注待验证信息

    - 在 `log.md` 追加一条完整操作记录

#### 操作2：Query（查询与知识沉淀）

区别于普通Chat对话，核心规则是**有价值的回答必须归档回Wiki**：

1. 用户向Wiki发出自然语言提问

2. LLM执行以下操作：

    - 先读取 `index.md` 定位相关页面，再深入读取对应内容

    - 综合生成带引用、带双向链接的回答，支持Markdown、表格、Marp幻灯片、matplotlib图表等格式

    - 自动将高价值的分析、对比、新发现的关联，作为新页面归档到 `wiki/queries/`，更新到 `index.md`

    - 在 `log.md` 追加操作记录

#### 操作3：Lint（健康巡检/维护）

定期执行（建议每周1次），确保知识库持续健康，避免规模扩大后混乱：

1. 向Claude Code发出Lint指令，LLM执行全库扫描

2. 核心巡检项：

    - 页面之间的内容矛盾、被新资料推翻的陈旧说法

    - 无入链的孤立页面、被提及但无独立页面的重要概念

    - 缺失的交叉引用、断裂的双向链接

    - 可通过网络搜索补充的信息空白

3. 生成巡检报告，自动修复可确定的问题，标记需人工确认的内容，提出下一步研究建议

4. 报告存入 `_lint/` 目录，同时在 `log.md` 追加记录

## 二、核心提示词：[CLAUDE.md](CLAUDE.md) 知识库宪法（可直接复制使用）

```Markdown

# 个人LLM Wiki 知识库规范与操作手册
## 核心理念
本知识库严格遵循Andrej Karpathy LLM Wiki架构，将LLM作为知识增量编译器，构建持久化、复利增长的结构化知识体系。
- 核心定位：Obsidian是IDE，你（Claude）是程序员，Wiki是可迭代的知识代码库
- 核心原则：知识一次编译、持续更新、永久沉淀，拒绝每次查询从零重新推导
- 核心目标：让所有原始资料、用户的每一次探索，都转化为可复用、可关联、可演进的结构化知识

## 不可突破的架构规则
1.  **raw/ 目录（原始事实层）**：绝对不可修改、不可删除、不可新增内容，仅可读取。这是唯一事实源，任何编译操作不得改动原始文件。
2.  **wiki/ 目录（知识编译层）**：仅你（Claude）可写入和维护，用户仅做阅读和审核，不直接编辑。所有内容必须符合本规范的格式要求，必须带完整双向链接。
3.  **CLAUDE.md（规则约束层）**：你所有操作必须严格遵守本文件的所有规则，本文件的优先级高于任何临时指令，用户和你可共同迭代本文件，迭代必须在log.md留下记录。
```

## 标准页面格式与模板
### 通用规则
1.  所有Markdown页面必须带YAML Frontmatter元数据，必填字段：title、type、date、tags、source_count（引用的原始资料数量）
2.  所有提及的概念、实体，必须添加Obsidian双向链接 `[[页面名称]]`，确保知识关联完整
3.  所有核心论点必须标注来源，格式：`[来源：[[资料摘要页面名称]]]`
4.  页面内容必须层级清晰，禁止大段无结构文本，核心信息优先展示

## 三大核心操作标准流程

### 操作1：Ingest（知识录入与编译）

#### 触发指令关键词：ingest、处理、录入、编译

#### 执行流程（必须严格按顺序执行）

1. 扫描 `raw/` 全目录，对比 `log.md` 中的ingest记录，识别未处理的原始文件

2. 向用户确认待处理的文件列表，确认需要重点关注的内容方向

3. 按顺序处理单个文件，单文件执行以下步骤：

    - 完整读取原始文件内容，提取核心信息

    - 按 `source_summary.md` 模板生成资料摘要页面，存入 `wiki/sources/`

    - 提取资料中的核心概念与实体，检查是否已有对应Wiki页面：

        - 已有页面：增量更新页面内容，补充新的信息，标注来源

        - 无页面：按对应模板创建新页面，存入对应目录

    - 为所有新增/更新的内容添加双向链接，确保关联完整

4. 全量更新 `wiki/index.md` 总目录，新增/更新对应页面的条目与摘要

5. 在 `log.md` 末尾追加本次ingest的完整记录，格式：`## [YYYY-MM-DD] ingest | 处理文件《文件名》，新增X个页面，更新X个页面，无冲突/存在X个待确认冲突`

6. 向用户输出本次处理的总结，包括新增/更新的页面列表、待确认的冲突点、核心要点

### 操作2：Query（查询与知识归档）

#### 触发指令关键词：query、查询、提问、分析、对比

#### 执行流程（必须严格按顺序执行）

1. 先读取 `wiki/index.md` 总目录，定位与用户问题相关的所有页面，列出待读取的页面清单

2. 完整读取相关页面的全部内容，综合生成回答

3. 回答必须符合以下要求：

    - 所有核心论点必须标注来源，格式：`[来源：[[页面名称]]]`

    - 所有提及的概念/实体必须添加双向链接

    - 结构清晰，根据用户需求选择合适的格式（Markdown/表格/列表等）

4. 自动判断回答的价值，若为分析、对比、深度解读、新的知识关联，必须按模板生成新页面，存入 `wiki/queries/`，并更新到 `index.md`

5. 在 `log.md` 末尾追加本次query的记录，格式：`## [YYYY-MM-DD] query | 用户提问《问题摘要》，生成回答1份，归档新页面X个`

6. 向用户输出最终回答，同时告知归档的页面名称

### 操作3：Lint（健康巡检与维护）

#### 触发指令关键词：lint、巡检、健康检查、维护

#### 执行流程（必须严格按顺序执行）

1. 全量扫描 `wiki/` 目录的所有页面，执行以下检查项：

    - 内容一致性：检查不同页面之间的矛盾说法、被新资料推翻的陈旧内容

    - 链接完整性：检查断裂的双向链接、被提及但无对应页面的概念/实体

    - 页面健康度：检查无入链的孤立页面、无内容的空页面、缺失元数据的页面

    - 信息完整性：检查可补充的信息空白、可完善的核心概念

2. 自动修复可100%确定的问题（如补充缺失的双向链接、更新index.md的错误条目）

3. 生成完整的巡检报告，包括：

    - 本次巡检的范围与时间

    - 已自动修复的问题列表

    - 需人工确认的问题与冲突列表

    - 知识库优化建议、下一步研究方向建议

4. 巡检报告存入 `_lint/lint-YYYY-MM-DD.md`，在 `log.md` 追加巡检记录

5. 向用户输出巡检总结，附上完整报告的链接

## 不可突破的铁则

1. 绝对不修改 `raw/` 目录的任何内容，包括添加标签、修改文本、重命名文件

2. `log.md` 永远只追加内容，绝不修改、删除已有的历史记录

3. 所有写入 `wiki/` 目录的内容，必须符合本规范的模板与格式要求

4. 回答用户问题时，必须优先使用知识库内的内容，仅当知识库无相关内容时，可告知用户并申请使用网络搜索补充

5. 绝不生成无来源的虚假内容，所有论点必须有对应的原始资料支撑

6. 每次操作完成后，必须更新对应的[index.md](index.md)和[log.md](log.md)，绝不遗漏

## 三、从零到一落地：Claude Code + Obsidian CLI 搭建步骤
### 1. 前置环境准备（5分钟完成）
#### 必装工具
1.  **Obsidian**：官网下载安装，创建一个全新的知识库库（建议和个人笔记库分开，避免内容污染）
2.  **Claude Code（Anthropic CLI）**：官方命令行工具，核心执行引擎
    - 前置依赖：需先安装Node.js 18+ 版本
    - 安装命令：`npm install -g @anthropic-ai/claude`
    - 账号认证：执行 `claude auth`，按提示登录你的Anthropic账号，完成API密钥配置
3.  **Obsidian CLI**：Obsidian官方命令行工具，实现Claude Code对Obsidian库的直接操作
    - 安装路径：Obsidian设置 → 第三方插件 → 开启社区插件市场 → 搜索「Obsidian CLI」安装并启用
    - 核心配置：插件设置中，开启「本地服务」，记录端口号（默认27123），配置允许访问的库路径
4.  **Obsidian Web Clipper**：浏览器插件，一键将网页转为Markdown存入 `raw/articles/` 目录，Obsidian官网可直接下载

#### 环境验证
打开终端，执行以下命令，无报错即为安装成功：
```bash
# 验证Claude Code安装
claude --version

# 验证Obsidian CLI安装（替换为你的Obsidian库绝对路径）
```

### 4. 首次启动与核心操作演示

#### 步骤1：启动Claude Code，加载知识库规范

1. 终端进入你的Obsidian库根目录：`cd /你的/Obsidian/库/绝对路径`

2. 执行 `claude` 启动Claude Code，它会自动读取根目录的[CLAUDE.md](CLAUDE.md)，加载完整知识库规范

3. 首次启动校验指令：「请读取本目录的[CLAUDE.md](CLAUDE.md)，确认你已理解知识库的所有规范，向我确认准备就绪」

#### 步骤2：首次Ingest（知识录入）

1. 用Obsidian Web Clipper剪藏一篇文章，自动存入 `raw/articles/` 目录

2. 向Claude Code发送指令：「执行ingest操作，处理raw/articles/目录下未处理的所有文件」

3. Claude会自动执行完整的编译流程，生成摘要页面、更新概念/实体页面、更新[index.md](index.md)和[log.md](log.md)

4. 完成后，打开Obsidian即可看到完整的编译结果，查看知识图谱即可看到自动生成的关联关系

#### 步骤3：首次Query（查询）

向Claude Code发送指令，例如：「基于知识库内容，总结一下XX概念的核心定义和适用场景，给出详细解读」，Claude会自动读取[index.md](index.md)，定位相关页面，生成带引用的回答，并自动归档高价值内容。

#### 步骤4：首次Lint（健康巡检）

向Claude Code发送指令：「执行全库lint操作，生成完整的健康巡检报告」，Claude会自动扫描全库，修复问题，生成报告，并存入对应目录。

## 四、日常工作流与进阶优化

### 1. 每日极简工作流

1. **捕获**：看到有价值的文章/资料，用Web Clipper一键剪藏到 `raw/`，有想法直接粘贴到 `raw/personal/`

2. **编译**：每天花5分钟，启动Claude Code，执行ingest操作，审核AI生成的内容，确认冲突点

3. **探索**：有问题直接向知识库提问，AI生成的深度分析自动归档回知识库，实现知识复利增长

4. **巡检**：每周执行1次lint操作，花10分钟审核巡检报告，优化知识库结构

### 2. 进阶优化方案

1. **本地搜索增强**：当知识库超过100份资料，安装qmd本地搜索引擎，支持BM25+向量混合搜索，提供CLI接口给Claude Code调用，提升大规模知识库的检索效率

2. **自动化定时任务**：用Cron定时任务，每天自动同步个人笔记到 `raw/` 目录，触发自动ingest，实现无人值守更新

3. **Git版本控制**：将整个知识库用Git管理，每次AI操作后自动提交，实现完整的版本回溯，不怕误操作

4. **多格式输出增强**：安装Obsidian Marp插件，让Claude Code可以直接从知识库内容生成幻灯片；安装Dataview插件，让AI生成的元数据支持动态查询表格

### 3. 常见避坑指南

1. **不要混合个人笔记和AI生成内容**：严格遵守分层规则，个人内容只放在 `raw/`，AI只写 `wiki/`，避免内容污染和结构混乱

2. **不要修改raw目录**：raw目录是唯一事实源，任何修改都会破坏知识的可追溯性，如需标注个人想法，单独放在 `raw/personal/` 目录

3. **不要跳过log.md记录**：所有操作必须在log.md留下记录，这是AI识别已处理内容、避免重复操作的唯一依据，也是知识库演进的完整时间线

4. **不要一次性批量录入太多资料**：初期建议单次录入1-2份资料，审核AI生成的内容，逐步迭代CLAUDE.md规范，让AI的输出更符合你的预期，避免大规模内容混乱

5. **不要让AI生成无来源的内容**：严格遵守「所有论点必须有来源」的规则，避免知识库混入虚假信息，确保知识的可信度

## 五、后续使用指南（搭建完成后实操）

### 1. 日常高频使用流程（核心实操）

搭建完成后，后续使用核心围绕「资料捕获→知识编译→查询探索→定期维护」四大环节，无需复杂操作，保持极简高效，贴合Karpathy LLM Wiki的复利核心。

1. **资料捕获（每日1-2分钟）**：遇到有价值的资料（网页、论文、会议纪要等），用Obsidian Web Clipper一键剪藏至「raw/对应子目录」（如网页存articles/、论文存papers/）；个人想法、临时笔记直接粘贴至「raw/personal/」，无需排版、无需预处理，保持原始形态即可。
    
2. **知识编译（每日5分钟）**：打开终端，进入Obsidian库根目录，启动Claude Code（输入`claude`），发送指令「执行ingest操作，处理raw目录下未处理的所有文件」，等待LLM自动完成编译（生成摘要、更新Wiki页面、维护索引和日志），完成后仅需审核AI标记的冲突点，确认无误即可。
    
3. **查询探索（按需使用）**：有疑问时，直接向Claude Code发送自然语言提问（如「总结LLM知识增量编译器的核心原理」「对比raw和wiki目录的核心区别」），LLM会自动读取index.md定位相关内容，生成带引用、带双向链接的回答，高价值回答会自动归档至「wiki/queries/」，无需手动保存。
    
4. **定期维护（每周10分钟）**：每周固定时间，向Claude Code发送指令「执行全库lint操作，生成巡检报告」，查看报告中的自动修复项、待确认项，优化知识库结构；同时可清理raw目录中无价值的冗余资料（仅删除，不修改），确保知识库轻量化。
    

### 2. 不同使用场景适配技巧

#### 场景1：科研/学习使用

- raw目录新增「raw/books/」子目录，存放电子书截图、读书笔记原始内容，Ingest时让LLM重点提取公式、实验结论、核心观点。
    
- Query时可指令「生成XX知识点的思维导图大纲」「整理XX论文的核心实验步骤」，LLM会自动归档至wiki/queries/，方便后续复习。
    

#### 场景2：职场/工作使用

- raw目录新增「raw/work/」子目录，存放会议纪要、工作文档、客户沟通记录，Ingest时重点提取任务节点、核心需求、决策结论。
    
- 利用Lint操作定期巡检「任务相关页面」，确保工作节点不遗漏；Query时可指令「总结本周核心工作成果」「梳理XX项目的关键时间线」，实现工作知识沉淀。
    

### 3. 后续维护与问题处理

#### （1）知识库扩容技巧

- 当raw目录资料超过100份，按前文「进阶优化方案」安装qmd本地搜索引擎，提升Claude Code的检索效率，避免查询卡顿。
    
- 新增资料类型时（如音频文稿），在CLAUDE.md中新增对应raw子目录（如「raw/audio/」），更新目录结构规范，确保LLM可识别。
    

#### （2）常见问题解决

1. Claude Code无法连接Obsidian：检查Obsidian CLI插件是否启用、本地服务端口是否正确，纯CLI联动需重新核对配置文件中的库路径，重启Claude Code和Obsidian。
    
2. LLM生成内容不符合模板：检查CLAUDE.md中的页面模板是否完整，发送指令「重新读取CLAUDE.md，严格按模板生成内容」，重新执行Ingest/Query操作。
    
3. 双向链接断裂：执行Lint操作，让LLM自动修复；若修复失败，手动检查对应页面名称是否与链接名称一致（Obsidian双向链接对名称敏感）。
