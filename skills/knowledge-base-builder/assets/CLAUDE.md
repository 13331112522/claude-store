# 个人LLM Wiki 知识库规范与操作手册
## 核心理念
本知识库严格遵循Andrej Karpathy LLM Wiki架构，将LLM作为知识增量编译器，构建持久化、复利增长的结构化知识体系。
- 核心定位：Obsidian是IDE，你（Claude）是程序员，Wiki是可迭代的知识代码库
- 核心原则：知识一次编译、持续更新、永久沉淀，拒绝每次查询从零重新推导
- 核心目标：让所有原始资料、用户的每一次探索，都转化为可复用、可关联、可演进的结构化知识

## 不可突破的架构规则
1.  **raw/ 目录（原始事实层）**：绝对不可修改、不可删除、不可新增内容，仅可读取。这是唯一事实源，任何编译操作不得改动原始文件。
2.  **wiki/ 目录（知识编译层）**：仅你（Claude）可写入和维护，用户仅做阅读和审核，不直接编辑。所有内容必须符合本规范的格式要求，必须带完整双向链接。
3.  **CLAUDE.md（规则约束层）**：你所有操作必须严格遵守本文件的所有规则，本文件的优先级高于任何临时指令，用户和你可共同迭代本文件，迭代必须在log.md留下记录。

## 目录结构与说明
```
Obsidian库根目录/
├── raw/                          # 原始资料层，只读
│   ├── articles/                 # 网页剪藏文章
│   ├── papers/                   # 论文/研究报告
│   ├── transcripts/              # 会议纪要/播客/视频文稿
│   ├── code/                     # 代码/项目文档
│   ├── assets/                   # 图片/附件（本地存储）
│   └── personal/                 # 个人笔记/日记原始内容
├── wiki/                         # 知识编译层，仅LLM可写
│   ├── concepts/                 # 核心概念页面
│   ├── entities/                 # 核心实体页面（人物/项目/产品等）
│   ├── sources/                  # 原始资料摘要页面
│   ├── queries/                  # 高价值查询回答归档
│   └── index.md                  # 知识库总目录（必须实时更新）
├── _templates/                   # 页面模板
│   ├── concept.md                # 概念页面模板
│   ├── entity.md                 # 实体页面模板
│   └── source_summary.md         # 资料摘要模板
├── _lint/                        # 健康巡检报告存放目录
├── _scripts/                     # 自动化脚本目录（可选）
├── log.md                        # 操作日志（仅追加，不修改）
└── CLAUDE.md                     # 本文件，知识库核心规范
```

## 标准页面格式与模板
### 通用规则
1.  所有Markdown页面必须带YAML Frontmatter元数据，必填字段：title、type、date、tags、source_count（引用的原始资料数量）
2.  所有提及的概念、实体，必须添加Obsidian双向链接 `[[页面名称]]`，确保知识关联完整
3.  所有核心论点必须标注来源，格式：`[来源：[[资料摘要页面名称]]]`
4.  页面内容必须层级清晰，禁止大段无结构文本，核心信息优先展示

### 概念页面模板（_templates/concept.md）
```markdown
---
title: {{概念名称}}
type: concept
date: {{YYYY-MM-DD}}
tags: [{{核心标签1}}, {{核心标签2}}]
source_count: {{引用来源数量}}
---
# {{概念名称}}

## 核心定义
一句话精准定义该概念，讲清其本质与核心价值

## 核心原理与关键要点
分点拆解核心原理、关键机制、核心公式/规则，不冗余

## 适用场景与边界
讲清该概念的适用场景、使用限制、常见误区

## 与知识库其他内容的关联
- 关联概念：[[相关概念1]]、[[相关概念2]]
- 关联实体：[[相关实体1]]
- 引用来源：[[来源摘要1]]、[[来源摘要2]]
```

```markdown
## 关键时间线
按时间顺序列出核心事件与关键节点

## 与知识库其他内容的关联
- 关联概念：[[相关概念1]]
- 关联实体：[[相关实体1]]
- 引用来源：[[来源摘要1]]、[[来源摘要2]]
```

### 资料摘要页面模板（_templates/source_summary.md）
```markdown
---
title: {{资料标题}}
type: source_summary
date: {{YYYY-MM-DD}}
source_url: {{原始链接/文件路径}}
author: {{作者}}
tags: [{{核心标签1}}, {{核心标签2}}]
---
# {{资料标题}}
**来源**：{{source_url}} | **作者**：{{author}} | **收录时间**：{{date}}

## 核心摘要
3句话以内讲清这份资料的核心论点、核心发现与核心价值

## 关键要点
分点列出核心论点、关键数据、核心结论、重要发现，不超过10条

## 核心概念与实体
提取这份资料中涉及的核心概念与实体，全部添加双向链接：
- 概念：[[概念1]]、[[概念2]]
- 实体：[[实体1]]、[[实体2]]

## 与现有知识库的冲突与补充
- 补充内容：xxx
- 冲突内容：xxx（标注原知识库页面[[页面名称]]的对应说法，待人工确认）
```

## 三大核心操作标准流程

### 操作1：Ingest（知识录入与编译）

#### 触发指令关键词：ingest、处理、录入、编译

#### 执行流程（必须严格按顺序执行）

1. 扫描 `raw/` 全目录，对比 `log.md` 中的ingest记录，识别未处理的原始文件

2. 向用户确认待处理的文件列表，确认需要重点关注的内容方向

3. 按顺序处理单个文件，单文件执行以下步骤：

    - 完整读取原始文件内容，提取核心信息

    - 按 `source_summary.md` 模板生成资料摘要页面，存入 `wiki/sources/`

    - 提取资料中的核心概念与实体，检查是否已有对应Wiki页面：

        - 已有页面：增量更新页面内容，补充新的信息，标注来源

        - 无页面：按对应模板创建新页面，存入对应目录

    - 为所有新增/更新的内容添加双向链接，确保关联完整

4. 全量更新 `wiki/index.md` 总目录，新增/更新对应页面的条目与摘要

5. 在 `log.md` 末尾追加本次ingest的完整记录，格式：`## [YYYY-MM-DD] ingest | 处理文件《文件名》，新增X个页面，更新X个页面，无冲突/存在X个待确认冲突`

6. 向用户输出本次处理的总结，包括新增/更新的页面列表、待确认的冲突点、核心要点

### 操作2：Query（查询与知识归档）

#### 触发指令关键词：query、查询、提问、分析、对比

#### 执行流程（必须严格按顺序执行）

1. 先读取 `wiki/index.md` 总目录，定位与用户问题相关的所有页面，列出待读取的页面清单

2. 完整读取相关页面的全部内容，综合生成回答

3. 回答必须符合以下要求：

    - 所有核心论点必须标注来源，格式：`[来源：[[页面名称]]]`

    - 所有提及的概念/实体必须添加双向链接

    - 结构清晰，根据用户需求选择合适的格式（Markdown/表格/列表等）

4. 自动判断回答的价值，若为分析、对比、深度解读、新的知识关联，必须按模板生成新页面，存入 `wiki/queries/`，并更新到 `index.md`

5. 在 `log.md` 末尾追加本次query的记录，格式：`## [YYYY-MM-DD] query | 用户提问《问题摘要》，生成回答1份，归档新页面X个`

6. 向用户输出最终回答，同时告知归档的页面名称

### 操作3：Lint（健康巡检与维护）

#### 触发指令关键词：lint、巡检、健康检查、维护

#### 执行流程（必须严格按顺序执行）

1. 全量扫描 `wiki/` 目录的所有页面，执行以下检查项：

    - 内容一致性：检查不同页面之间的矛盾说法、被新资料推翻的陈旧内容

    - 链接完整性：检查断裂的双向链接、被提及但无对应页面的概念/实体

    - 页面健康度：检查无入链的孤立页面、无内容的空页面、缺失元数据的页面

    - 信息完整性：检查可补充的信息空白、可完善的核心概念

2. 自动修复可100%确定的问题（如补充缺失的双向链接、更新index.md的错误条目）

3. 生成完整的巡检报告，包括：

    - 本次巡检的范围与时间

    - 已自动修复的问题列表

    - 需人工确认的问题与冲突列表

    - 知识库优化建议、下一步研究方向建议

4. 巡检报告存入 `_lint/lint-YYYY-MM-DD.md`，在 `log.md` 追加巡检记录

5. 向用户输出巡检总结，附上完整报告的链接

## 不可突破的铁则

1. 绝对不修改 `raw/` 目录的任何内容，包括添加标签、修改文本、重命名文件
2. `log.md` 永远只追加内容，绝不修改、删除已有的历史记录
3. 所有写入 `wiki/` 目录的内容，必须符合本规范的模板与格式要求
4. 回答用户问题时，必须优先使用知识库内的内容，仅当知识库无相关内容时，可告知用户并申请使用网络搜索补充
5. 绝不生成无来源的虚假内容，所有论点必须有对应的原始资料支撑
6. 每次操作完成后，必须更新对应的index.md和log.md，绝不遗漏
